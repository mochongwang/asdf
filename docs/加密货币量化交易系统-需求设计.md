# 加密货币量化交易系统 - Java 21 版本完整需求设计文档

## 一、系统概述
本系统是基于 Java 21 LTS 构建的生产级加密货币量化交易系统，仅支持币安交易所，获取交易所数据、加工相关数据、执行策略、下单、记录成交订单、统计盈利。

## 二、技术选型

| 层级 | 技术选择 | 说明 |
| --- | --- | --- |
| 语言 | Java 21 | 最新LTS版本，虚拟线程优化高并发场景 |
| Web框架 | Spring Boot 3.1.0 | 完全支持Java 21，官方推荐 |
| 数据获取 | 原生WebSocket + restful (Binance) | K线/OrderBook/账户信息统一使用WebSocket |
| 下单 | 原生restfulapi | Spring WebClient 处理 |
| 数据库 | DuckDB | DuckDb api |
| 缓存 | Caffeine 3.1.9 | Java 21完全兼容，性能优化 |
| 加密 | Java JCE (AES + PBKDF2) | Java 21标准库支持 |
| WebSocket | Java-WebSocket | 轻量级WebSocket库，无额外依赖 |
| JSON解析 | Fastjson2 | 高性能 |

### 1. 数据库表

#### 1.1 策略主表 (strategies)
```sql
CREATE TABLE strategies (
id VARCHAR NOT NULL UNIQUE,                 -- UUID，策略唯一标识
name VARCHAR NOT NULL,                     -- 策略名称/标识
symbol VARCHAR NOT NULL,                   -- 交易对: BTC/USDT
stop_loss_pct DOUBLE DEFAULT 5.0,        -- 止损百分比，如5表示5%
take_profit_pct DOUBLE DEFAULT 10.0,     -- 止盈百分比，如10表示10%
leverage INTEGER DEFAULT 10,               -- 杠杆倍数，如10表示10倍
maxamount INTEGER DEFAULT 10,      --  最大下单金额，如10表示10 USTD
trigger_period VARCHAR NOT NULL,           -- 触发周期: 1m/5m/15m/1h/4h/1d
use_orderbook INTEGER DEFAULT 0,           -- 是否使用orderbook: 0=否/1=是
strategy_path VARCHAR NOT NULL,            -- 策略代码标识符，如 ma_cross
enabled BOOLEAN DEFAULT false,              -- 是否启用: false=停止/true=运行中
status VARCHAR DEFAULT 'stopped',          -- 状态: stopped/running/error
created_at TIMESTAMP DEFAULT NOW(),        -- 创建时间
updated_at TIMESTAMP DEFAULT NOW()         -- 更新时间
);
```

#### 1.2 策略指标明细表 (strategy_indicators)
```sql
CREATE TABLE strategy_indicators (
id VARCHAR NOT NULL UNIQUE,                -- UUID，记录唯一标识
strategy_id VARCHAR NOT NULL,             -- 外键，关联strategies.id
indicator_name VARCHAR NOT NULL,        -- 指标名称/标识
indicator_type VARCHAR NOT NULL,           -- 指标类型: ma/macd/rsi/boll/kdj/cci/volume/vwap/atr
indicator_params VARCHAR,                   -- 指标参数JSON，如 {"fast":12,"slow":26,"signal":9}
period VARCHAR NOT NULL,                   -- 指标周期: 1m/5m/15m/1h/4h/1d
created_at TIMESTAMP DEFAULT NOW(),       -- 创建时间
updated_at TIMESTAMP DEFAULT NOW()         -- 更新时间
);
```

#### 1.3 订单表 (orders)
```sql
CREATE TABLE orders (
    id BIGINT AUTOINCREMENT,                     -- 订单ID
    order_id VARCHAR,                            -- 交易所订单ID
    local_order_id VARCHAR NOT NULL,             -- 本地订单UUID
    strategy_id VARCHAR,                         -- 策略ID
    exchange VARCHAR NOT NULL,                   -- 交易所
    symbol VARCHAR NOT NULL,                     -- 交易对
    side VARCHAR NOT NULL,                       -- 方向: OPEN_LONG/CLOSE_LONG/OPEN_SHORT/CLOSE_SHORT
    position_side VARCHAR,                       -- 持仓方向: LONG/SHORT
    order_type VARCHAR NOT NULL,                 -- 订单类型: MARKET/LIMIT
    amount DOUBLE NOT NULL,                      -- 委托金额(USDT)
    quantity DOUBLE,                             -- 委托数量
    price DOUBLE,                                -- 限价
    stop_loss_ratio DOUBLE,                      -- 止损比例
    take_profit_ratio DOUBLE,                    -- 止盈比例
    stop_loss_price DOUBLE,                      -- 止损价格
    take_profit_price DOUBLE,                    -- 止盈价格
    status VARCHAR DEFAULT '买入挂单',             -- 状态:买入挂单/已成交/已撤单
    filled_quantity DOUBLE DEFAULT 0,            -- 已成交数量
    filled_price DOUBLE,                         -- 成交价格
    leverage INTEGER DEFAULT 1,                  -- 杠杆
    commission DOUBLE DEFAULT 0,                 -- 手续费
    timeout_seconds INTEGER DEFAULT 300,         -- 超时秒数
    cancel_on_timeout BOOLEAN DEFAULT true,      -- 超时是否撤单
    cancel_reason VARCHAR,                       -- 撤单原因
    error_message VARCHAR,                       -- 错误信息
    order_remark VARCHAR,                        -- 订单备注
    created_at TIMESTAMP DEFAULT NOW(),          -- 创建时间
    updated_at TIMESTAMP DEFAULT NOW(),          -- 更新时间
    filled_at TIMESTAMP                          -- 成交时间
);
```

#### 1.4 账户表 (accounts)

CREATE TABLE accounts (

### 2. 界面UI功能

1. **登录页面**
   - 输入用户名密码即可，这个用户名密码是代码里写死的。

2. **策略列表**
   - 对应策略主表（只显示主表字段）。
   - 基本的增删改查需要支持。
   - 策略列表右上角有个新建按钮，点击弹出新建策略的页面（新建编辑页面尽可能多的选择框、下拉框方便用户选择，避免数据错误）。
   - 策略列表每一行“策略名称”是个超链接，点击弹出策略详情。
   - 策略列表第一列是操作列，有以下按钮：
     - **启用策略**：当本策略未启用的时候可以点击，点击后进行：数据订阅和策略加载等操作。
     - **取消策略**：当策略启用的时候可以点击，点击后进行：策略强行平仓，取消数据订阅及相关资源。
     - **策略回测**：点击的时候弹出页面，需要选择开始日期时间和结束日期时间，测试交易金额，点击确定，就开始走回测程序。类似启动策略，下面会详细说明。跑完程序后，需要统计下单多少次，每单盈利情况。

3. **订单列表**
   - 只支持查询，支持分页，按时间创建时间倒序，可以按交易对、状态、创建时间筛选。

4. **账户表**
   - 只支持查询。

5. **通知日志表**
   - 只支持查询，可以按照全字段查询。

### 3. 系统启动需要运行的程序时序

1. 启动JVM
2. 启动websocket
3. 更新杠杆信息表，没有websocket接口，就用restful
4. 更新账户信息表，通过websocket，并且监控账户信息变动
5. 监控订单信息，通过websocket，监控订单信息更新订单表

### 4. 用户操作开启策略系统运行时序

1. 输入用户名密码进入系统。
2. 进入策略列表。
3. 点击新建，新建一个策略（主表上的触发周期和明细表的周期需要校验，主表上的触发周期必须和明细表上的一条数据的周期一致）。
4. 新建完成后，去列表上点击启动策略。
5. 点击后，系统要做的事，如下：
   - 将当前策略表缓存到系统内存。
   - 将主表的币种和明细表的周期组合起来，然后开始订阅K线。
     - 订阅k线的时候，需要预先加载200根历史k线，然后websocket再订阅实时k线，websocket的k线只要x=true的，k先需要缓存，缓存的key是币种_周期，例如：BTC_1h。
     - 然后全部计算好对应的指标，然后缓存，缓存的key要是保持和明细表的指标名称一样。
   - 主表的是否使用orderbook，如果是是。就需要通过websocket建立一个50档的orderbook并且增量更新，缓存起来，key是币种。并且提供方法取前几档的数据。
   - 策略程序的触发，这个要看主表上的触发周期，当对应周期的k线x=true的时候，触发主表上记录的程序。并传入币种、周期。
   - 策略程序，获取币种和周期就可以通过缓存去取其他数据。
   - 策略当调整适合的时候需要去触发下单。
   - 下单程序，提供方法，让策略程序调用：
     - 做多，市价止盈止损，杠杆，超时撤回（秒），订单备注（记录到订单表）。
     - 做空，市价止盈止损，杠杆，超时撤回（秒），订单备注（记录到订单表）。
     - 做多，限价止盈止损，杠杆，超时撤回（秒），订单备注（记录到订单表）。
     - 做空，限价止盈止损，杠杆，超时撤回（秒），订单备注（记录到订单表）。
     - 强行平仓，传入币种，对现有该币种的所有订单强行平仓（不管多空），订单备注（记录到订单表）。
   - 下单（或平仓）的时候记录到订单表，并且记录日志，发送通知。
   - 订单状态变更的时候，都要修改记录，并且发送通知。
   - **策略回测功能**：策略列表上的策略回测按钮点击。
     - 点击的时候弹出页面，需要选择开始日期时间和结束日期时间，测试交易金额，点击确定，就开始走回测程序。
     - 回测程序类似策略启动，k线数据循环调用策略，缓存的key默认在前面加个HC_。
     - 策略程序这时候取的数据会和正常跑策略有区别，取的时候记得加HC_。
     - 下单的时候也是模拟下单，相当于全部是市价单，价格按K线收盘价来。
     - 最后统计这段时间共下单多少单和盈利情况。返回到页面上做个简单列表显示。
   - 策略程序，需要提供个模板给我，我来实现接口，如果以后要改，我就按模板来改。
   - 本系统需要支持多策略。
