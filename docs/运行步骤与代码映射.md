# 按需求文档的运行步骤与代码映射说明（最新版）

> 本文档用于回答：需求文档里的关键运行步骤，在当前代码中对应哪个类、哪个方法。

---

## 一、系统启动时序（需求文档第 3 节）

### 1）启动 JVM
- 入口类：`com.example.quant.QuantApplication`
- 入口方法：`main(String[] args)`

### 2）启动 Web 服务与基础组件
- Spring 启动后执行：`startup/SystemStartupRunner#run(...)`
- 作用：输出启动时序日志、发送系统启动通知。

### 3）更新杠杆信息
- 服务：`service/LeverageService`
- 启动日志在 `SystemStartupRunner` 中会输出当前杠杆记录数量。

### 4）账户信息与订单信息监控
- 主同步服务：`service/BinanceUserStreamService`
  - `createListenKey()` / `keepAliveListenKey()` / `ensureUserStreamConnected()`
  - 用户流事件：`outboundAccountPosition` -> `AccountService#upsertSnapshot(...)`
  - 用户流事件：`executionReport` -> `OrderService#syncExecutionReport(...)`
  - 可靠性：listenKey 失效轮换 + 连接退避重连
- 补偿同步服务：`service/ExchangeUserDataSyncService`（请求式轮询）

---

## 二、数据获取层（按当前约束实现）

> 当前策略：**取数据只用 WebSocket API（ws-api）**。

### 1）Ticker 获取（ws-api）
- 类：`data/BinanceRestClientImpl`
- 方法：`tickerPrice(String symbol)`
- ws-api method：`ticker.price`

### 2）K线获取（ws-api）
- 类：`data/BinanceRestClientImpl`
- 方法：`klinesByWsApi(String symbol, String interval, int limit)`
- ws-api method：`klines`

### 3）OrderBook 获取与增量维护
- 快照拉取：`data/BinanceRestClientImpl#depth(String symbol, int limit)`（ws-api `depth`）
- 增量订阅：`data/OrderBookSubscriptionService`
  - `subscribe(...)` / `unsubscribe(...)`
  - `DepthListener#onText(...)` 处理 depth 增量
  - `applyDepthEvent(...)` 做 `U/u` 连续性校验，断档自动重拉快照
  - `topLevels(...)` 提供前N档读取
- 策略联动：`StrategyEngineService#enable/disable` 根据 `useOrderBook` 自动订阅/取消

### 4）统一数据入口与缓存
- 类：`data/MarketDataService`
- 方法：`latestTicker(...)`、`latestKlines(...)`、`topLevelsOrderBook(...)`
- 缓存：ticker / kline / indicator / orderbook（Caffeine）

### 5）币安对接失败重试与通知
- 类：`data/MarketDataService`
- 方法：`retryOnce(...)`
- 策略：失败后重试 1 次；仍失败则调用 `NotificationService.notify(...)` 并抛异常。

---

## 三、指标计算层

> 当前策略：**指标统一用 TA-Lib Core**。

### 1）核心实现类
- 类：`data/IndicatorCalculator`
- 依赖：`com.tictactec.ta.lib.Core`

### 2）当前已实现指标
- MA（SMA）：`movingAverage(...)`
- RSI：`rsi(...)`
- MACD（histogram）：`macd(...)`
- ATR：`atr(...)`
- BOLL：`bbands(...)`（支持 upper/middle/lower）
- KDJ：`stoch(...)`（支持 K/D/J）
- CCI：`cci(...)`
- VWAP / VOLUME：按当前 K 线数组直接计算

### 3）策略触发前指标计算入口
- 类：`data/MarketDataService`
- 方法：`calculateIndicators(...)`

---

## 四、策略层执行时序

### 1）创建策略并做周期校验
- 控制器：`web/StrategyController#create(...)`
- 服务：`service/StrategyService#create(...)`
- 校验：`StrategyService#validatePeriods(...)`

### 2）启用策略
- 控制器：`StrategyController#enable(...)`
- 引擎：`strategy/StrategyEngineService#enable(...)`

### 3）触发策略
- 手动触发接口：`StrategyController#trigger(...)`
- 引擎执行：`StrategyEngineService#triggerOnce(...)`
- 典型执行链：
  1. 拉 ticker
  2. 拉 K 线
  3. 计算指标
  4. 组装 `StrategyRuntimeContext`
  5. 调用 `StrategyTemplate#evaluate(...)`

### 4）示例策略
- 类：`strategy/DemoMaStrategy`
- 规则：MA 金叉开多、死叉平多。

### 5）自动触发调度
- 类：`scheduler/StrategyTriggerScheduler`
- 方法：`run()` 周期触发 `StrategyEngineService#triggerAllActive()`。

---

## 五、下单层

> 当前策略：**下单只用 REST API**（真实模式）。

### 1）真实下单客户端
- 接口：`order/BinanceTradeClient`
- 实现：`order/BinanceTradeClientImpl`
- 方式：REST 下单 + HMAC SHA256 签名

### 2）统一下单入口
- 类：`order/OrderService`
- 方法：`placeOrder(...)`
- 行为：
  - `app.trading.simulation=true`：模拟下单
  - `app.trading.simulation=false`：真实 REST 下单

### 3）下单失败重试与通知
- 类：`order/OrderService`
- 方法：`placeOrder(...)`
- 策略：失败后重试 1 次；仍失败则 `notify` + 抛异常。

---

## 六、回测引擎映射

- 入口：`web/StrategyController#backtest(...)`
- 服务：`service/BacktestService#runBacktest(...)`
- 当前模型：
  - HC_ 命名空间隔离（避免污染实时缓存）
  - MA 信号回放
  - 止盈/止损/超时平仓
  - 手续费 + 滑点 + 信号到成交延迟 bar
  - 输出：订单明细 + 总收益 + 总手续费 + 胜率 + 最大回撤

---

## 七、通知系统

- 统一入口：`service/NotificationService#notify(...)`
- 查询：`service/NotificationService#query(...)`
- 接口：`GET /api/notifications`
- webhook：`notify/WeComWebhookClient#sendText(...)`
- 触发点：系统启动、策略启停、下单提交、重试后失败等
