# 按需求文档的运行步骤与代码映射说明

> 本文档用于回答：需求文档里每个“系统运行步骤”，在当前代码里由哪个类、哪个方法执行。
> 
> 说明：当前版本是可运行骨架，部分步骤已提供扩展点（TODO），便于你继续落地完整生产能力。

---

## 一、系统启动时序（对应需求文档第 3 节）

### 步骤 1：启动 JVM
- **入口类**：`com.example.quant.QuantApplication`
- **入口方法**：`main(String[] args)`
- **执行说明**：Spring Boot 在这里启动整个应用上下文。

### 步骤 2：启动 websocket
- **当前状态**：骨架版本暂未接入 Binance WebSocket 客户端。
- **现有对应**：`MarketDataService` + `BinanceRestClientImpl` 先通过 REST 提供行情能力。
- **建议扩展位置**：`com.example.quant.data` 包下新增 WebSocket 客户端类，例如 `BinanceWsClient`，在 Spring 启动后自动连接。

### 步骤 3：更新杠杆信息表（无 websocket，用 restful）
- **当前状态**：骨架版本暂未实现杠杆信息拉取与入库。
- **可复用基础**：
  - `BinanceRestClientImpl`：统一 REST 调用入口。
  - `ApiConcurrencyGuard#execute(...)`：调用时自动并发+频控保护。
- **建议扩展位置**：新增 `LeverageSyncService#syncLeverageInfo()`，启动时触发。

### 步骤 4：更新账户信息表（通过 websocket，并监控变动）
- **当前状态**：骨架版本暂未实现账户流 websocket。
- **建议扩展位置**：
  - data 层新增 `AccountStreamService`
  - order/account DAO 层新增账户更新方法

### 步骤 5：监控订单信息（websocket 更新订单表）
- **当前状态**：骨架版本暂未实现订单流 websocket。
- **当前可用逻辑**：
  - `OrderService#placeOrder(...)` 会先写本地订单记录（内存）。
  - `OrderController#list()` 可查询当前记录。
- **建议扩展位置**：新增 `OrderStreamService` 监听成交回报并更新订单状态。

## 二、用户“开启策略”运行时序（对应需求文档第 4 节）

### 步骤 1：输入用户名密码进入系统
- **当前状态**：骨架版本暂未加登录鉴权（需求里是“写死账号密码”）。
- **当前页面入口**：`PageController#index()` 返回 `templates/index.html`。

### 步骤 2：进入策略列表
- **当前状态**：骨架版本暂未做完整“策略列表页面”，但已提供策略 API。
- **对应接口**：`StrategyController#list()`。

### 步骤 3：点击新建策略，并做周期校验
- **当前新建接口**：`StrategyController#create(StrategyRequest req)`。
- **当前状态**：已支持基础字段创建；
  需求里的“主表触发周期必须匹配明细表某条周期”校验，当前因明细尚未持久化，暂未实现。
- **建议扩展点**：在 `create(...)` 内增加 `indicators` 入参后进行周期一致性校验。

### 步骤 4：新建完成后点击启动策略
- **接口**：`POST /api/strategies/{id}/enable`
- **方法**：`StrategyController#enable(String id)`
- **核心执行**：`StrategyEngineService#enable(StrategyDefinition definition)` 将策略放入 `activeStrategies` 缓存。

### 步骤 5：启动后系统要做的事情（逐条对应）

#### 5.1 将当前策略缓存到系统内存
- **实现方法**：`StrategyEngineService#enable(...)`
- **缓存结构**：`activeStrategies`（`ConcurrentHashMap`）。

#### 5.2 组合币种 + 周期订阅 K 线；预加载 200 根历史 K；只取 x=true K 线；缓存 `币种_周期`
- **当前状态**：骨架版尚未接入 K 线 websocket 和历史 K 拉取。
- **当前替代能力**：`MarketDataService#latestTicker(symbol)` 可读取最新价格并缓存。
- **建议扩展点**：
  - data 层新增 `KlineService#preloadHistory(...)`
  - data 层新增 `KlineStreamService#subscribe(...)`
  - 缓存建议放在 data 层统一管理。

#### 5.3 计算指标并按指标名缓存
- **当前状态**：骨架版未实现真实指标计算。
- **当前模板入口**：`StrategyTemplate#evaluate(...)`。
- **示例实现**：`DemoMaStrategy#evaluate(...)`（仅演示结构）。

#### 5.4 use_orderbook=true 时维护 50 档 orderbook 并增量更新，支持取前 N 档
- **当前状态**：骨架版未实现 orderbook 流。
- **建议扩展点**：data 层新增 `OrderBookService`，并在策略上下文中注入读取接口。

#### 5.5 当触发周期 K 线 x=true 时触发策略程序，并传币种+周期
- **当前触发方式**：手动触发接口
  - `StrategyController#trigger(String id)`
  - `StrategyEngineService#triggerOnce(String strategyId, String strategyPath)`
- **上下文传递**：`StrategyRuntimeContext(symbol, triggerPeriod, latestTicker)`。

#### 5.6 策略程序通过缓存读取其他数据
- **当前已具备**：`MarketDataService` 内部 Caffeine 缓存。
- **当前策略读取入口**：`evaluate(...)` 的 `context` 参数。

#### 5.7 策略满足条件后触发下单
- **流程**：
  1. `StrategyEngineService#triggerOnce(...)` 调用策略模板 `evaluate(...)`
  2. 若返回 `PlaceOrderCommand`，则调用 `OrderService#placeOrder(...)`

#### 5.8 下单能力（多/空、市价/限价、止盈止损、杠杆、超时撤回、备注）
- **当前命令对象**：`PlaceOrderCommand`
  - 已包含：方向、类型、金额、限价、止盈止损百分比、杠杆、超时、备注等参数。
- **当前落地状态**：`OrderService#placeOrder(...)` 先内存记录，真实交易所下单待接入。

#### 5.9 强行平仓（按币种）
- **当前方法**：`OrderService#forceCloseBySymbol(String symbol, String remark)`
- **当前状态**：示例实现会记录一条“强平提交”订单。

#### 5.10 下单/平仓记录订单、日志、发送通知
- **当前状态**：
  - 订单记录：已实现（`OrderService` 内存记录）
  - 日志通知：未接企业微信 webhook
- **建议扩展点**：新增 `NotificationService#send(...)`，并在下单与状态变更处调用。

#### 5.11 订单状态变更修改记录并通知
- **当前状态**：需在未来接入订单 websocket 回报后实现。

#### 5.12 策略回测（HC_ 前缀缓存、模拟市价按收盘价）
- **当前状态**：骨架版未实现回测引擎。
- **建议扩展点**：strategy 层新增 `BacktestService`。

#### 5.13 策略模板可维护
- **已实现接口**：`StrategyTemplate`
- **用途**：你后续新增策略时，只需新增一个实现类，并返回唯一 `strategyPath()`。

#### 5.14 支持多策略
- **已实现基础能力**：`StrategyEngineService` 的 `activeStrategies` 为 Map，可同时存多策略。

## 三、并发控制是如何执行的（你特别关注）

### 1）为什么能控制普通用户并发
- 统一通过 `ApiConcurrencyGuard` 控制请求进入节奏：
  - `MAX_IN_FLIGHT = 3`：最多 3 个并发在途请求。
  - `REQUESTS_PER_SECOND = 8`：每秒最多 8 个请求令牌。

### 2）在哪里生效
- `BinanceRestClientImpl#tickerPrice(...)` 每次调用都包在：
  - `guard.execute(() -> restClient.get()...)`

### 3）超限时行为
- 令牌或并发获取失败会抛出 `IllegalStateException`：
  - `触发频控：请稍后重试`
  - `触发并发限制：请稍后重试`

## 四、前端“尽量下拉选择，不手输”是如何实现的

### 1）后端统一下发可选项
- 接口：`UiOptionsController#options()`
- 输出：周期、指标类型、订单类型、交易对、策略模板、布尔选项。

### 2）页面按可选项渲染下拉框
- 页面：`templates/index.html`
- 逻辑：页面加载时 `fetch('/api/options')`，再动态填充 `select`。

## 五、建议你下一步优先补齐的实现顺序

1. 接入 DuckDB（策略、指标、订单、账户、通知、杠杆表）
2. 接入 Binance WebSocket（K线、账户、订单、orderbook）
3. 完成策略触发调度（按周期自动触发，不仅是手动触发）
4. 接入真实下单与订单状态同步
5. 增加通知（企业微信 webhook）
6. 完成回测引擎（HC_ 缓存隔离）
7. 增加登录鉴权（写死账号密码可先快速实现）
